# ACMineevo — программы для 1С:Далион автосервиса «Авто Центр Минеево»

Бывший «АвтоОтчёт» (до версии 0.9.0 программы назывались AvtoOtchet-*.exe; уже установленные
обновляются сами, имя файла на диске остаётся старым). Программы для Windows:

| Программа | Где стоит | Что делает |
|---|---|---|
| **ACMineevo-Buhgalter.exe** | ПК бухгалтера | Отправляет кассовую книгу (Excel) на ПК владельца. Больше ничего. |
| **ACMineevo-Vladelec.exe** | ПК владельца | Берёт данные из 1С, принимает книгу, сверяет, сгружает правильный отчёт на флешку, удаляет данные с ПК. |
| **ACMineevo-Marketing.exe** | маркетологу | CRM и «Простые звонки»: выгрузка CSV/JSON, проверка структуры CRM. |
| **ACMineevo-Vitrina.exe** | сервер 1С | Сайт-витрина: звонки, заказ-наряды, деньги, проблемные места (см. «Витрина»). |

## Как это работает

```
ПК бухгалтера                          ПК владельца
Касса октябрь.xlsx ─► копия во временную ─► шифрование ─► сеть ─► память программы
(оригинал не трогается)  папку, удаляется     (код доступа)            │
                         сразу после отправки                          ▼
                                          1С:Далион (COM) ─────► сверка кодом
                                                                       │
                                                                       ▼
                                                      отчёт .xlsx → флешка
```

* **Данные хранятся только в памяти программы владельца.** На диск ПК ничего не пишется,
  кроме настроек и журнала действий (без сумм и ФИО). «Удалить отчётность» и закрытие окна
  стирают всё. Из базы 1С **ничего не удаляется**: подключение только читает.
* **Передача по сети** зашифрована (AES-256-GCM). Ключ получается из общего
  «кода доступа», который вводится в обеих программах. Файл с неверным кодом не принимается.
* **Проверку делает код, без ИИ**, поэтому каждое расхождение можно проверить по номеру документа.

## Что проверяется

| Проверка | Пример |
|---|---|
| Нет в кассовой книге | ПКО №420 есть в 1С, в книге его нет |
| Нет в 1С | в книге ПКО №9999, в 1С такого документа нет |
| Сумма не совпадает | РКО №89: в 1С 34 000, в книге 35 000 |
| Дата не совпадает | ПКО №451 в 1С от 17.10, в книге от 18.10 |
| Дубль в книге | один документ записан дважды |
| Остаток на начало дня ≠ 1С | показывается в день, когда расхождение появилось или изменилось |
| Неверный «Итого за день» / остаток на конец | арифметика внутри самой книги |
| Номер отличается (предупреждение) | номер записан иначе, но совпали дата и сумма |

## Отчёт на флешке

Файл `Кассовая книга ДД.ММ.ГГГГ-ДД.ММ.ГГГГ (проверено).xlsx`:
1. **Итог проверки** — сравнение остатков, прихода и расхода «1С против книги», вердикт.
2. **Расхождения** — полный список с пояснениями.
3. **Кассовая книга (по 1С)** — правильная книга по дням: остаток на начало, операции,
   итог за день, остаток на конец.
4. **Книга бухгалтера** — её записи с отметкой «OK / ошибка» у каждой строки.

В файле только значения, без формул: он открывается заполненным в любом режиме Excel.

## Формат кассовой книги

Программа сама находит колонки по заголовкам. Понимает:
* печатную форму **КО-4** из 1С: «КАССА за 01.10.2026», «Остаток на начало дня»,
  колонки «Номер документа / От кого получено или кому выдано / Приход / Расход»,
  «Итого за день», «Остаток на конец дня»;
* обычную таблицу: `Дата | № | Приход | Расход` или `Дата | № | Вид | Сумма`.

Нужен файл **.xlsx**. Если бухгалтер сохраняет в .xls или .mxl, пусть пересохранит
в .xlsx.

## Установка

1. Скопировать папку на ПК с Python 3.10+ и запустить **`build.bat`**. В папке `dist`
   появятся оба .exe. Python нужен только для сборки, на ПК бухгалтера и владельца
   он не нужен.
2. **ПК владельца:** запустить `ACMineevo-Vladelec.exe`. При первом запуске Windows
   спросит про доступ к сети: разрешить для **частных сетей**. В блоке «Данные» будет
   строка «адрес этого ПК: 192.168.x.x · порт 50505». Код доступа — в «Настройках».
3. **ПК бухгалтера:** запустить `ACMineevo-Buhgalter.exe` → «Настройки» → ввести адрес,
   порт и код доступа с ПК владельца.

Для приёма файла программа владельца должна быть открыта.

## Работа на сервере через удалённый рабочий стол (основной вариант)

У 1С программная лицензия, привязанная к серверу, поэтому программа владельца
запускается **на сервере**, внутри удалённого рабочего стола владельца.

1. **На сервере, один раз:** командная строка от администратора:
   ```
   regsvr32 "C:\Program Files\1cv8\8.3.27.2325\bin\comcntr.dll"
   netsh advfirewall firewall add rule name="AvtoOtchet 50505" dir=in action=allow protocol=TCP localport=50505
   netsh advfirewall firewall add rule name="AvtoOtchet poisk 50506" dir=in action=allow protocol=UDP localport=50506
   ```
   Второе правило нужно, чтобы бухгалтер мог отправить книгу на сервер, третье - чтобы
   программа бухгалтера сама находила программу владельца в сети.
2. Положить `ACMineevo-Vladelec.exe` на сервер, например в `C:\AvtoOtchet`.
3. «Настройки» → «1С:Далион через COM» → путь к базе `C:\1C\Dalion`, поле «База на сервере»
   пустое, пользователь 1С и пароль → «Проверить подключение и показать кассы».
4. **На ПК владельца**, в подключении к удалённому рабочему столу: «Показать параметры» →
   «Локальные ресурсы» → «Подробнее…» → ☑ «Диски» и ☑ «Диски, которые будут подключены
   позже» → подключиться. Вставленная флешка появится в программе как
   «E: на вашем компьютере (через удалённый стол)».
5. **У бухгалтера** в настройках достаточно ввести код доступа: программа сама найдёт
   программу владельца в сети (кнопка «Найти» или автоматически при отправке). Если адрес
   сервера сменится, она найдёт его заново.

Данные по-прежнему живут только в памяти программы и стираются кнопкой
«Удалить отчётность» или при закрытии окна.

## Обновления через GitHub

В обеих программах есть кнопка **«⟳ Обновления»**. Сама программа GitHub не проверяет:
только по нажатию кнопки. Если вышла новая версия, программа показывает, что нового, скачивает свой .exe,
проверяет подпись, заменяет себя и открывается заново. У владельца данные в памяти при
этом удаляются, как при закрытии. Программа предупредит об этом.

**Защита.** Каждый .exe подписан ключом Ed25519. Закрытый ключ хранится только в секретах
GitHub, открытый зашит в программу. Файл без верной подписи, от другой программы или другой
версии не ставится. Скачанная из интернета «новая версия» без подписи ничего не сделает.

### Настройка (один раз)

1. На GitHub создать **публичный** репозиторий `avtootchet` (имя и владелец указаны в
   `avtootchet/update_config.py`, поле `REPO`). Включить двухфакторный вход в аккаунт GitHub.
2. В папке проекта:
   ```
   .venv\Scripts\python.exe tools\make_update_key.py
   ```
   Открытый ключ запишется в `update_config.py`, закрытый в `%USERPROFILE%\avtootchet_update_key.txt`.
3. GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret:
   имя `UPDATE_SIGNING_KEY`, значение = содержимое `avtootchet_update_key.txt`. Сам файл
   потом перенести в надёжное место (флешка, менеджер паролей) и удалить с диска. Без него
   новые версии подписать не получится.
4. Отправить проект в репозиторий:
   ```
   git init
   git add .
   git commit -m "АвтоОтчёт"
   git branch -M main
   git remote add origin https://github.com/<логин>/avtootchet.git
   git push -u origin main
   ```
5. Выпустить первую версию с обновлением: `release.bat 0.2.0 "Автообновление"`.
   Её .exe один раз поставить на сервер и ПК бухгалтера вручную (из Releases). Дальше
   программы обновляются сами.

### Выпуск новой версии

**Через Pull Request (основной способ).** Изменения приходят отдельной веткой с новым номером
в `avtootchet/__init__.py`. На GitHub: Pull requests → открыть → **Merge pull request** →
Confirm. После слияния GitHub Actions сам соберёт и опубликует версию; «Что нового» берётся
из заголовка Pull Request. Если номер версии не менялся, сборка пропускается.

**Со своего компьютера:**
```
git add .
git commit -m "что поменял"
release.bat 0.3.0 "Что нового - это увидят при обновлении"
```

GitHub Actions соберёт обе программы, прогонит тесты, подпишет и опубликует релиз
(вкладка **Actions**, 5–10 минут). Номер версии должен быть больше предыдущего.
После слияния Pull Request обновите свою копию: `git pull`.

Программа должна лежать в папке, куда пользователь может писать (например `C:\AvtoOtchet`,
а не `Program Files`). Иначе обновление сообщит, что нет прав.

## Отчёт по выручке (из 1С, без бухгалтера)

Кнопка **«Отчёт по выручке»** в блоке «Данные»: программа забирает из 1С все оплаты за выбранный
период, строит лист выручки в привычном виде, открывает его в Excel для проверки и после
«Отправить» записывает на выбранную флешку.

* Направление и способ оплаты — по кассе: «… (М)» — Металлообработка; Эквайринг — Терминал,
  QR — QR код, «БЧ» — наличные без чека, остальные «Нал…» — наличные с чеком. Для общей кассы
  наличных с чеком направление берётся из подразделения ПКО.
* Оплата по заказ-наряду делится на Работы и Запчасти (Товары + Материалы) пропорционально
  составу заказ-наряда; оплата по расходной накладной — Продажа запчастей и Продажа масла
  (группы номенклатуры с маслом — настройка `oil_groups`, по умолчанию «Масло»).
* Возвраты (РКО на основании заказ-наряда или накладной) — минусом.
* **Сверка с 1С** (лист «Сверка»): по каждой кассе за каждый день приход и расход по регистру
  денег Далиона сравниваются с тем, из чего они должны складываться (ПКО выручки и прочие,
  возвраты, прочие РКО, перемещения). «Другие документы» ≠ 0 — значит, кассу двигало что-то,
  что не попало в отчёт; такие строки красные, итог сверки виден и в окне программы.
* **Расходы** (листы «Расходы по статьям», «Расходы по поставщикам», «Расходы подробно»): все
  документы «Расход денег» из касс и с расчётных счетов. Группа — статья затрат, а где статьи нет —
  вид движения денежных средств; возвраты покупателям — отдельной строкой. Основные поставщики
  (настройка «Основные поставщики», по умолчанию Берг, Тимасан, Вюрт, Амтек, Гринлайт) ищутся по
  части названия контрагента и показываются отдельным блоком.
* **Аналитика** (каждый раздел строится отдельно: если 1С отвергнет запрос, на листе будет текст
  ошибки, а остальной отчёт построится):
  * «Прибыль» — регистр «Продажи»: продажа, себестоимость, зарплата механиков, сторонние работы,
    валовая прибыль, наценка на запчасти; ниже — деньги за период по организациям (выручка − расходы);
  * «Динамика» — сравнение с прошлым таким же периодом и тем же периодом год назад, выручка по
    месяцам за 12 месяцев, две диаграммы;
  * «Эквайринг и СБП» — оплаты в кассы терминала/QR против перечислений на счёт, комиссия банка
    (она же попадает в расходы как «Комиссия банка: …»);
  * «Долги клиентов» — заказ-наряды за 12 месяцев, где сумма больше оплат (с учётом возвратов и бонусов);
  * «Механики» — регистр «ЗаказНаряды»: нормочасы и суммы работ по механикам, суммы и средний чек
    по мастерам-приёмщикам.
* Листы: Выручка по дням, Итоги, Прибыль, Динамика, Сверка, Эквайринг и СБП, Оплаты подробно, Расходы… (клиент, автомобиль, госномер, мастер, № ЗН),
  Перемещения ДС, Остатки касс, Прочие поступления (без основания — не выручка), Замечания.

## Состав отчёта

Кнопка **«Состав отчёта…»** рядом с «Отчёт по выручке»: галочками выбираются листы, которые войдут
в отчёт, порядок — кнопками ↑ ↓ или перетаскиванием. Для таблиц-списков («Оплаты подробно» — она же
для «Прочие поступления» и «Замечания», «Расходы подробно», «Долги клиентов», «Перемещения ДС»)
справа так же выбираются и расставляются колонки. «По умолчанию» — все листы и колонки. Настройка
хранится в программе; новые листы из следующих версий добавляются в конец включёнными.

## Залежавшиеся запчасти (склад)

Кнопка «Залежавшиеся запчасти» и **утренний отчёт без окна** (`ACMineevo-Vladelec.exe --stock-report`,
задача Windows). Что в отчёте:
* **Залежавшиеся** — запчасти на складе, пришедшие по приходной накладной N и больше дней назад
  (N — «Лежат дольше» в настройках, по умолчанию 14). Остаток раскладывается по приходам от новых
  к старым: продаются старые партии, лежит остаток последних. Колонки: дата прихода, дней лежит,
  номер накладной, поставщик, кто провёл (пользователь 1С), менеджер, сумма по цене прихода.
  Сначала самое старое и дорогое;
* **Под заказ-наряды** — пришли под конкретный заказ-наряд и лежат;
* **Выданы в ЗН** — выданы в заказ-наряд внутренней накладной, ЗН не закрыт;
* **По менеджерам**, **По поставщикам** — итоги.

Группы номенклатуры, в названии которых есть слова из «Не учитывать группы» (по умолчанию
«Расходные, Слесарные, Инструмент, Хозяйствен, Канцеляр, Спецодежд, Уборк, Вода»), не
учитываются; масло, антифриз и другие жидкости — учитываются. Лист «Группы» показывает все
группы и что из них учтено.

Утренний отчёт сохраняется в «Папку утреннего отчёта» (по умолчанию `F:\Отчёты\Склад`)
без пароля (галочка «Шифровать паролем» в настройках его включает); прежний удаляется после записи нового. Если отчёт построить
не удалось, старый остаётся, рядом появляется «ОШИБКА — отчёт не построен.txt».
Настройка задачи и ярлыка на папку — `tools/setup_stock_task.ps1` (запускать от пользователя
Windows, под которым настроена программа).

## Куда сохраняется отчёт и пароль

* Внизу окна «Куда сохранить»: вставленные флешки (в том числе через удалённый стол),
  ранее выбранные папки и пункт **«📁 Выбрать папку…»** — любая папка, в том числе сетевая.
* Каждый сохранённый отчёт **зашифрован паролем** (шифрование Excel, AES-256): Excel спрашивает
  пароль при открытии. Пароль задаётся в «⚙ Настройки» → «Пароль для отчётов» (не меньше
  6 символов) и хранится зашифрованным средствами Windows. Без пароля программа отчёт не
  сохраняет. Забытый пароль восстановить нельзя.
* Предпросмотр перед сохранением — это уже зашифрованный файл: Excel сразу спрашивает пароль
  для отчётов. Копия через «Сохранить как» тоже остаётся с паролем; незашифрованный отчёт
  на диск не попадает. Временная копия стирается сразу после решения.

## Порядок работы владельца

1. Выбрать период (или «Как в книге бухгалтера»).
2. «Получить данные из 1С».
3. Дождаться книги от бухгалтера (зелёный индикатор) или «Открыть файл вручную…».
4. «Проверить отчётность» → посмотреть расхождения.
5. Вставить флешку → выбрать её в списке → «Сгрузить на флешку». Отчёт сначала откроется
   в Excel для проверки: «Отправить» — записать на флешку, «Не отправлять» — отменить.
   Отправляется отчёт в том виде, как его построила программа: правки в Excel не учитываются.
   Временная копия для Excel стирается сразу после решения (если Excel ещё открыт —
   программа попросит его закрыть или сотрёт копию при закрытии/следующем запуске).
6. «Удалить отчётность».

## Источник данных 1С

В «Настройках» → «Данные 1С»:
* **Демо** — читает `export.json` из учебной базы «Автосервис», чтобы всё проверить без Далиона;
* **1С:Далион через COM** — читает регистр `ДенежныеСредства` конфигурации «АвтоБизнес»
  (Далион 1.3.6, платформа 8.3.27): движения наличных касс (без эквайринга) за период и остаток на начало.
  ПКО/РКО — это документы `ПриходДенег`/`РасходДенег`; остальные документы, которые
  двигали наличные (перемещения, чеки ККМ и т.п.), тоже попадают в сверку под своими названиями.
  Фильтры: «Организация» (кассовая книга ведётся по организации) и «Кассы».
  Кнопка «Проверить подключение и показать кассы» в настройках подключается к базе
  и выводит список наличных касс.
  Кнопка «Проверить структуру склада (без сумм)» показывает, какие документы двигают
  запчасти, какие у них реквизиты (ответственный, склад, заказ) и какими регистрами
  ведутся остатки — только названия и количества. Нужна для отчёта
  «закупили и не продали».
  Кнопка «Проверить данные для анализа процессов (без сумм)» показывает, за какой период
  хранится журнал регистрации 1С и какие события в него пишутся, какие документы есть
  за полгода, какие у заказ-наряда даты и статусы и какой документ на какой ссылается —
  только названия и количества, без сумм, клиентов и имён пользователей. Нужна для схемы
  бизнес-процессов (process mining) по данным 1С.

  Что нужно на ПК владельца:
  * клиент 1С **той же версии**, что на сервере, **64-битный**;
  * зарегистрированный `comcntr.dll` (от администратора:
    `regsvr32 "C:\Program Files\1cv8\<версия>\bin\comcntr.dll"`);
  * пользователь 1С с правом «Внешнее соединение» и чтением кассовых данных.

## Анализ процессов (PDF по ГОСТ)

Кнопка «Анализ процессов (PDF)» строит отчёт об анализе бизнес-процесса обслуживания по
заказ-нарядам за последние месяцы (по умолчанию 6) — без опроса сотрудников, только по данным
Далиона (только чтение). Каждый заказ-наряд — отдельный случай; шаги процесса берутся из его
реквизитов (создан, переведён в работу, завершён, выдан и кто это сделал) и из связанных документов
(приход запчастей под ЗН, выдача запчастей внутренней накладной, оплата).

В отчёте: фактическая схема процесса с числом ЗН и медианой времени переходов, самые частые варианты
процесса, длительность этапов (медиана, среднее, 90-й процентиль, по типам ЗН), соблюдение плановых
сроков, зависшие ЗН (перечень в приложении), нагрузка по дням, часам, сотрудникам и постам,
рекомендации, повторы и причины отказов, выводы и предложения.

Оформление по ГОСТ 7.32-2017: титульный лист, реферат, содержание, термины, введение, разделы,
заключение, список источников, приложение; А4, поля 30/15/20/20 мм, Times New Roman 14 пт,
полуторный интервал, нумерация страниц внизу по центру. Период, порог «зависшего» ЗН и название
организации для титульного листа — в «Настройках» → «Анализ процессов».

## Витрина (сайт)

Сайт для Саши и маркетолога: где компания теряет клиентов и деньги, как работают менеджеры.
Открывается по ссылке с ПК и телефона: в офисе `http://192.168.0.220:8765`, снаружи — только через
Tailscale `http://100.112.23.72:8765`.

* **Сбор** (`ACMineevo-Vitrina.exe --collect`, задача Windows в 06:00): только чтение Далиона за
  последние N месяцев (по умолчанию 6) — звонки «Простых звонков», заказ-наряды с суммами, оплаты в кассы
  по ЗН и расходным накладным (как «Выручка» владельца), работы из ЗН, задачи. Результат — один файл
  SQLite (`%APPDATA%\AvtoOtchet\vitrina.db`). Каждый раздел собирается отдельно: если один запрос 1С
  отвергнет, на сайте будет видно, какой.
* **Сайт** (`--serve`, задача «при включении»): разделы Главная, Проблемы, Телефония, Менеджеры, Финансы;
  фильтр по периоду, менеджеру и линии; с карточки — список конкретных случаев (CSV), со строки — история
  клиента «звонки → ЗН → оплаты».
* **Пароли**: владелец (всё) и маркетолог (без денег — суммы вырезаются на сервере, раздел «Финансы»
  закрыт). Хранятся отпечатки PBKDF2; 5 неверных паролей — пауза 5 минут. Номера телефонов на сайте —
  маской (последние 4 цифры), полностью — только если включено в настройках. В облако ничего не уходит.
* **Демо**: `--demo` или кнопка «Демо-сайт» — выдуманные данные, пароли `demo` и `marketing`.
* **Установка**: в окне программы задать подключение к 1С (пользователь только для чтения, видящий
  деньги), пароли сайта и названия линий (`21=Городской`), «Собрать данные сейчас». Затем от
  администратора: `tools\setup_vitrina.ps1 -Exe C:\avtootchet\ACMineevo-Vitrina.exe -User roma`.

Как считаются показатели — в начале `avtootchet/vitrina/metrics.py` (их же видно на сайте в подсказках).

## Для разработчика

```
avtootchet/common/    модели, шифрование, сеть, настройки (DPAPI), журнал, стиль
avtootchet/owner/     источники 1С, разбор книги, сверка, отчёт, флешки, окно владельца
avtootchet/accountant/окно бухгалтера
tools/make_demo_cashbook.py   демо-книги КО-4 (с ошибками и без)
tests/e2e_check.py            сквозной тест без экрана
```

* Запуск из исходников: `run_owner.bat`, `run_accountant.bat`.
* Тесты: `set QT_QPA_PLATFORM=offscreen && python tests\e2e_check.py`, `python tests\updater_check.py`.
* `avtootchet/common/updater.py` — проверка, скачивание, подпись, замена .exe; `update_ui.py` — кнопка.
* Настройки и журнал хранятся в `%APPDATA%\AvtoOtchet\`, технические ошибки — в `errors.log` там же.
